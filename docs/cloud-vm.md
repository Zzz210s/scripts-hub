# 为什么考虑云主机

## 现状:还没上云

三个程序现在**全部跑在本机的 Windows 计划任务**上(见 [local-deployment.md](local-deployment.md))。
搬到 Oracle Cloud 只是**规划**,尚未开通任何云主机 —— 卡在 Oracle 注册风控,见文末。

## 问题:这些程序需要一台「每天都在线、但没人操作」的机器

微软积分与微信读书签到都是「每天跑一次、跑完就走」的短任务。放在本机上就绑死在
「这台机器今天开着、且没在忙」上:出门、断电、系统更新重启、或者半夜关机,当天那一次就没了
(Windows 计划任务不补跑)。

## 备选方案与否定理由

| 方案 | 为什么用或不用 |
| --- | --- |
| **本机 Windows 计划任务** | **现状**。依赖本机在线,关机/休眠/忙碌时错过即丢;现在靠 14 小时时间窗内的多次触发尽量补上 |
| **GitHub Actions + cron** | 私有仓库的免费额度不够每天跑(这两个程序跑一次要几分钟到几十分钟,不是几秒);公开仓库又会暴露「哪个账号在刷什么」—— workflow 与提交历史谁都能看,cookie、邮箱等关联信息还可能进日志。另外 Actions 的定时触发会排队延迟,高峰期直接丢触发,不满足「一天必须跑一次」 |
| **自建 VPS / 树莓派** | 要么花钱,要么得自己买硬件、占电、占地方;树莓派还多一份维护 |
| **Oracle Cloud Always Free** | 选定它,但还没开通:ARM 实例(4 OCPU / 24 GB 内存)永久免费,够跑这两个 Node/Python 程序;Ubuntu 24.04 上 systemd timer + 状态文件就是我们要的调度与幂等 |

## 规划中的分工(尚未生效)

| 程序 | 计划跑在哪 | 为什么 |
| --- | --- | --- |
| 微软积分 | Oracle Cloud ARM(Ubuntu 24.04) | 纯 HTTP/脚本,无图形需求,适合常驻小机器 |
| 微信读书签到 | Oracle Cloud ARM(Ubuntu 24.04) | 同上;底座是 Python + 一个 HTTP 上报流程,能在无 GUI 环境跑 |
| 智慧树刷课 | 只在本机 Windows | Autovisor 用 Playwright 驱动本机 Chrome 播放视频,依赖图形会话;云主机没有它能用的桌面环境,也不该在无人看的服务器上放课件播放 |

真迁过去之后,本机的 Windows 计划任务可以保留为兜底(云主机哪天真没跑成,本机在线时还能补上),
但不再当主力。

## 代价:要管一台机器

云主机不是「配置完就永远不用管」。接受它就得接受这几件事:

- **运维**:系统更新、systemd 服务与定时器、磁盘与内存水位、日志轮转,都得有人看一眼。
- **网络**:Oracle 默认的安全列表和镜像自带的 iptables 两层防火墙都可能挡 SSH,入口规则要在
  两处都放(见 `scripts/wizard-oracle.sh` 第 3 阶段)。
- **ARM 容量**:Always Free 的 ARM 实例在热门区域经常容量不足,创建失败要在别的可用域/区域重试。
- **凭据**:云主机上也要维护微信读书的 `read-request.curl`、只读 API Key、企业微信群机器人地址
  这些会过期的凭据;私有目录的权限要收紧。
- **安全边界**:一旦放行 22 端口,公网就在扫它 —— 用密钥登录、禁密码、必要时换非标准端口。

## 现在卡在哪

用 ZA Bank(众安银行,香港)的 Visa 扣账卡注册 Oracle,报错是**地址字段格式校验**
(`Enter a valid value for Address Line 1`),与卡种无关。专项调研(结论:ZA Bank × Oracle
目前零成功案例,但香港扣账卡有成功先例)认为真正卡住的是「国家 / 地址 / 电话 / IP 四者自洽」
这一层。进展可查:`~/.config/automation-suite/vm.env` 仍是空的,说明
`scripts/wizard-oracle.sh` 没走完。

开通之后的调度与守卫见 [scheduling-convention.md](scheduling-convention.md) 的云端部分。
