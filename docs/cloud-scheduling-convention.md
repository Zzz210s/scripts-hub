# 云主机调度约定(错峰 + 一天一次幂等)

从 Windows 计划任务搬到云主机后,触发骨架不变,但**"错过不补跑"这个前提没了**:云主机 7×24 在线,
定时器一定能触发。所以云端版的重点从"抢时间窗"变成**"每个程序各自幂等,一天真跑一次"**——
定时器只是给机会,不该因为多触发几次就多跑几次。

## 触发骨架(每个程序相同)

1. **systemd timer 定点触发**,一天触发一到几次;不用"登录后延迟"那一套(云主机没有登录事件)
2. **程序自己守卫**:状态文件说今天已完成就直接退出(退出码 0,不通知);
   所以定时器**多触发几次是安全的**,不需要精确到分钟
3. **错峰仍要保留**:云主机是 Always Free 的 ARM(小内存),两个程序同一秒起来会抢内存、
   抢出口 IP、抢同一份浏览器/HTTP 会话

## 错峰规则(每个程序一个槽位)

| 程序 | 触发时刻(云主机本地时区) | 周期 | 幂等依据 |
| --- | --- | --- | --- |
| 微软积分(`microsoft-rewards.timer`) | 08:00 | 每天一次(可选:每 2 小时一次,靠守卫只跑第一次) | 当天已达成 / 尝试次数上限 |
| 微信读书签到(`weread-signin.timer`) | 08:30 | 每天一次 | 当天有效阅读已满 5 分钟 / 当日目标已完成 |
| (下一个程序) | 09:00 | 每天一次 | 同上 |

- 每个程序占一个 **30 分钟槽位**,新程序顺延(08:00 → 08:30 → 09:00 …),避免同一时刻并发
- 时刻用云主机本地时区(建议 `sudo timedatectl set-timezone Asia/Shanghai`),不用 UTC,便于和日报对表
- 想要"窗口内重试"就再加几条 `OnCalendar=`,守卫会把没意义的重复挡掉;不想要就只留一条

## 运行前检查同伴(peer lock)

每个程序启动后、联网之前,先走**本地段守卫**:

1. 今天是否已完成(自己的状态文件)——已完成直接退出
2. **同伴是否在跑**:读同伴的锁文件(约定放在 `~/.local/state/automation-suite/<程序>.lock`,
   内容 JSON,含 `pid` 与 `startedAt`)——任一在跑就跳过本次
3. 残锁处理:锁里的 `pid` 已不存在(或用 `flock` 就不会有残锁)就视为没在跑

**flock 是第一选择**:Linux 下用 `flock` 拿排他锁,进程一死锁自动释放,不存在 Windows 那种
"崩溃留下残锁"的问题。写 JSON 锁文件只在需要跨语言/跨机器读取时作为补充。

**跳过要说明原因**:跳过时在日志写一行(程序名 / 原因 / 下次机会),
需要通知用户的跳过(如凭据失效、内存不足)才发提醒;纯粹的"同伴在跑""今天已经跑过"这类
不需要人做任何事的常见原因**只写日志、不推送**,按下面的频率规则压住。

## 通知约定(沿用本机版,2026-10-04 修订)

- 一次运行最多两条:**开始一条 + 结束一条**
- 跳过类提醒:**同一天同一种原因最多一条**,文案必须回答"发生了什么 / 为什么 / 接下来会怎样"
- **不需要人做任何事的跳过不再推送**(同伴在跑 / 今天已经跑过 / 已达标 / 安静时段),只写日志
- 需要人工处理的情况(凭据失效、读不到数据)不受频率限制,每次提醒
- 跳过提醒的额度记在各程序的 `state`/`data` 目录下的通知状态文件;`--dry` 预览不消耗额度

## 守卫分两段(沿用本机版)

1. **本地段(不联网,应 < 1 秒)**:暂停 / 当天已达标 / 尝试次数已用尽 / 同伴在跑 / 安静时段
2. **联网段**:凭据体检与续期、官方数据读取

本地段不满足时**不要访问网络**——云主机按流量和请求数都省,更重要的是别在凭据已失效时
反复打对方接口。

## 新程序接入清单

1. 写一对 unit:`<程序>.service`(Type=oneshot,`ExecStart=` 指向运行器)+ `<程序>.timer`
   (`OnCalendar=` 按上表取槽位,`Persistent=false`——云端不需要补跑)
2. 运行器开头加本地的幂等守卫 + 同伴检查;状态与日志写在 `~/.local/state/automation-suite/` 或程序目录
3. 排他:用 `flock`;需要跨程序读取时再补 JSON 锁文件
4. 槽位按上表顺延,并在本文件登记
5. 接入后跑一次 `systemctl --user list-timers` 核对触发时刻,手动 `systemctl --user start <程序>.service` 验证守卫能正确跳过/执行
