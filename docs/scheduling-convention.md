# 自动化程序的调度约定(对齐 + 错峰)

本机所有"自动化程序"共用同一套触发骨架,但**必须错峰** —— 避免同一时刻抢内存、抢网络、
抢同一条出口 IP(微软积分与微信读书都在跑浏览器/HTTP 会话)。

## 触发骨架(每个程序相同)

1. **登录后延迟 N 分钟**触发一次:机器刚开机时网络与系统未必就绪
2. **白天时间窗内周期性给机会**:关机或忙碌时错过的那一次会直接丢失(Windows 计划任务不补跑),
   靠窗口内的下一次机会补上

## 错峰规则

| 程序 | 登录延迟 | 白天起始 | 周期 | 时间窗 |
| --- | --- | --- | --- | --- |
| 微软积分(`MicrosoftRewardsScript`) | 3 分钟 | 08:00 | 每 120 分钟 | 14 小时 |
| 微信读书签到(`WeReadSignIn`) | 10 分钟 | 08:30 | 每 60 分钟 | 14 小时 |
| (下一个程序) | 17 分钟 | 09:00 | 每 60 分钟 | 14 小时 |

- 每个程序占一个 **30 分钟槽位**,新程序顺延(08:00 → 08:30 → 09:00 …)
- 登录延迟按 **7 分钟步进**错开(3 → 10 → 17 …)
- 程序开始运行前检查**同伴的锁文件**(`logs/run.lock`,JSON 含 `pid`),任一在跑就跳过本次:
  宁可等到下一个机会,也不要两个程序同时压这台机器

## 通知约定(2026-10-02 定,2026-10-04 修订)

- 一次运行最多两条:**开始一条 + 结束一条**
- 跳过类提醒:**同一天同一种原因最多一条**,文案必须回答"发生了什么 / 为什么 / 接下来会怎样"
- **不需要人做任何事的跳过(已达标 / 同伴在跑 / 安静时段)不再推送**,只写运行日志;
  可能让今天白丢的(内存不足 / 尝试次数用尽 / 临近关机 / 已手动暂停)照旧推送
- 需要人工处理的情况(凭据失效、读不到数据)不受频率限制,每次提醒
- 跳过提醒的额度记在各程序的 `data/notify-state.json`;`--dry` 预览不消耗额度

## 启动流程约定

守卫分两段:

1. **本地段(不联网,应 < 1 秒)**:暂停 / 当天已达标 / 尝试次数 / 同伴在跑 / 安静时段 / 距关机避让 / 内存不足
2. **联网段**:凭据体检与续期、官方数据读取

本地段不满足时**不要访问网络**。同伴是否在跑以**对方自己的 `lock-status`** 为准(它知道残锁与进程实况),只在查不通时才按锁年龄兜底。

## 新程序接入清单

1. 用同一套运行器:`scripts\windows\` 下的 `run-daily.bat` + `run-daily.vbs`(隐藏窗口)
   + `run-state.js`(锁/配额/内存/强杀)+ 看门狗 + XML 注册脚本
2. 单实例锁写在 `logs\run.lock`,内容 `{"pid":<pid>,"startedAt":"<ISO>"}`(同伴要靠它判断)
3. 在 `.env` 里用 `BUSY_PEERS=` 列出同伴的锁文件路径(逗号分隔,正斜杠)
4. 槽位与登录延迟按上表顺延,并在本文件登记
5. 运行前守卫至少包含:同伴在跑 / 当天已完成 / 安静时段 / 关机避让 / 内存不足
